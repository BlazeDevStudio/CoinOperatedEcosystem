# Standalone Rental API v1 — read-only lab contract

Endpoint: GET /cgi-bin/blazerental?action=status&device_id=ID&nonce=NONCE&sig=HMAC

- ID: 24 lowercase hex; generated by local blazerentalctl register.
- NONCE: 32 lowercase random hex from the client (128 bits).
- sig: 64 hex HMAC-SHA256 of ASCII v1|status|ID|NONCE, keyed by the 32-byte device secret printed once on registration.
- Successful JSON: {"ok":true,"api_version":1,"device_id":"...","server_time":UNIX_SECONDS,"lease_until":UNIX_SECONDS,"nonce":"...","proof":"..."}.
- proof: 64 lowercase hex HMAC-SHA256 of v1|status-reply|ID|NONCE|SERVER_TIME|LEASE_UNTIL, same secret.
- Error: {"ok":false,"error":"request rejected"}. No secret is returned by CGI. There are no remote write commands in v1.

Local CLI: blazerentalctl init, register, grant ID SECONDS TRANSACTION_ID, status ID. A transaction ID is 12–64 ASCII alphanumerics, _ or -; reuse with identical inputs returns previous result with replayed=true; reuse with conflicting inputs is rejected. Valid seconds: 1–2592000. The state store is a single TSV file containing D device and R receipt rows. Rename serializes state+receipt into one updated file under exclusive directory lock. Failed/corrupt state refuses writes.

Preconditions: valid clock and working entropy/OpenSSL; only trusted local admin can use the CLI. This is NOT payment processing or secure Android enrollment. Phone-side countdown is display-only. TLS, command replay hardening, secure key distribution, storage/directory fsync, power-interruption proof and Android Device Owner enforcement are production blockers.
